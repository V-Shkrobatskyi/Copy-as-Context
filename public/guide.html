Choose the right amount of context

Without

Keeps every captured semantic node, not all HTML text on the page. Use it when completeness of the captured context matters more than length.

Detailed

Removes unnamed wrappers without semantic attributes, preserving text, links and states for careful review.

Compact

Removes repeated accessibility noise while retaining meaningful controls. This is the default.

Maximum

Preserves Compact context using selective abbreviations and repeated text or structures. A short legend explains the output; pages fall back to Compact when packing adds overhead. Token savings depend on the page and model.

Export format

Choose Semantic Text for a concise outline or Markdown when you want formatting in your notes or AI chat.

Save preferences stores your compression, format, and privacy choices for the next time you open the popup.

Keyboard shortcuts

On Chrome and Firefox Desktop, run actions from the current page without opening the popup: Alt+Shift+P for Preview & edit, Alt+Shift+C for Copy page context, Alt+Shift+S for Save to file, and Alt+Shift+E for Select element. On macOS, use Option+Shift with the same letters.

Shortcuts use saved preferences or defaults, together with current organization policies. Preview, Copy and Save capture the whole page; use the picker panel to export a selected block. Keep the source page focused for Copy. The extension icon briefly shows a check mark on success or ! on failure; hover over it for details. Save opens a temporary extension tab that closes after saving; keep it open until completion. Firefox asks for download permission when needed. Repeated shortcuts are ignored while an action is running.

Choose Keyboard shortcuts in the popup footer to change or remove assignments. Chrome uses chrome://extensions/shortcuts. In Firefox, use Manage Extension Shortcuts in the tools menu at about:addons if the shortcut manager does not open directly. Browser, system and other extension shortcuts may conflict. Check your assignments and keyboard layout, especially if Alt+Shift switches input languages.

Customize redaction filters

Choose Customize inside Redact sensitive data. The table lists the existing filters. Toggle a row, or choose + Add filter to add a named literal text filter in the same table, such as a client name or internal domain. Edit custom filters directly in their rows. Enable Case sensitive when letter case matters. Literal types do not interpret Regex or wildcard syntax. Choose Regex when you need pattern matching. Matches become [REDACTED]; overlapping filters may hide the same text. Password input values are always omitted by capture.

Choose one Rule type in each custom row. Text hides literal alternatives. Field labels hides values and nested text when a label contains a matching term; Field labels — whole words requires word boundaries. Both keep the field label visible. URL parameters hides query values for names such as token / client_key, keeping names and unrelated parameters visible. Enter parameter names without ?, &, =, # or line breaks.

Other types recognize Authorization values, JWTs and Assigned secrets. Regex replaces the separate GitHub, AWS and OpenAI custom types; existing rules are converted automatically with their original prefixes and case settings. Use Duplicate to create an editable equivalent of a configurable built-in filter, then edit its names, prefixes or Regex expression. Disable the original if your copy should replace it. Built-in types are fixed; Case sensitive is editable except for automatic detection types.

For literal types, separate alternatives with / (space, slash, space), such as pass / private code. Commas and ordinary URL/path slashes are literal. Text — single literal treats the entire matching rule as one phrase, preserving older rules. Older rules with several modes become separate rows. To check the same terms in two places, add two rows with different types.

Mask email addresses (including domains) is enabled by default: abcdef@gmail.com becomes abc***@gm***.com. The name and each domain label keep half their characters, rounded down and capped at three visible characters; the final domain suffix remains visible. One-character parts become *. Hide email addresses is off by default and hides the whole address when enabled. Full hiding from overlapping rules always wins, regardless of row order. Both types work automatically without matching text or case settings, recognize common email formats, and follow the master Redact sensitive data setting. Masking is stable on repeated processing.

Hide payment card numbers and Hide IBANs are on by default. Card-shaped numbers need 13–19 digits and a valid Luhn checksum; IBANs need a recognized country length and valid MOD-97 checksum. Spaces are accepted, as are hyphens in card numbers. Checksums do not prove that a card or account exists.

Mask phone numbers is on by default: it keeps half the digits, rounded down and capped at three, and masks the rest while preserving formatting. For example, +380 50 123 4567 becomes +380 ** *** ****. Full phone hiding overrides masking, regardless of row order.

Mask personal field values (English labels) is also on by default. Names and addresses keep half their characters, rounded down and capped at three: Al → A*, Anna → An**, Alexander → Ale******. Phone values keep formatting and email values use the existing name/domain mask. Documents, dates of birth, financial details and CVV/CVC are hidden completely. Labels stay visible; nested value text is protected too. Both mask types work without matching text or case settings, stay stable on repeated processing, and yield to full hiding.

Hide phone numbers is off by default. It recognizes phone-shaped numbers with + or 00 prefixes, or English Phone, Telephone, Tel, Mobile or Fax labels followed by : or =. English phone field labels also provide context for local field values and their nested text. It accepts 8–15 digits; unlabelled local numbers stay visible. These three automatic types need no matching text or case setting.

Hide personal field values (English labels) is off by default. It uses a fixed automatic type to hide values and nested text under labels such as Full name, Email, Phone, Address, Date of birth, Passport, SSN, Tax ID, Card number, CVV, IBAN or Bank account. It keeps labels visible. Enable it to hide whole Email field values instead of masking them. It does not detect names or addresses in ordinary prose; its fixed English label list is shown in Text / matching rule for both Hide and Mask.

For Regex, choose Insert example… in the row to start with email addresses, GitHub tokens, AWS keys, OpenAI keys or order IDs. The selection replaces the expression after confirmation when needed. Enter Regex without surrounding slashes or flags; use | for alternatives. Case sensitive sets default case matching. Expressions use the RE2 syntax subset: lookarounds and backreferences are not supported. Empty matches are ignored, existing redaction markers are preserved, and every nonempty match is hidden in full. Examples target common formats; email matching does not cover every valid address.

Expand Try filters. Test all checks enabled rules; Test selected checks only the rule chosen in the list, even if it is off, without changing its saved state. Both use unsaved edits. Matched rules shows which rules match the original input; their individual counts can overlap. Load example and Load near miss insert synthetic samples using the chosen rule’s current terms. Regex samples are provided for the preset expressions; paste your own sample for other expressions.

Leave Field label blank for plain text, or enter a label such as API key to test field values. The result includes the field label when provided. Sample text is not saved. Choose Save filters to apply changes to future exports when redaction is on. Existing previews are unchanged. Restore defaults removes custom rules and restores built-in defaults in the form; save to apply it.

Custom rules offer Text, Text — single literal, Field labels, Field labels — whole words, URL parameters, Authorization, JWT, Assigned secrets and Regex. Automatic email, phone, card, IBAN and personal-field types are built-in only and have no Duplicate action. Use their On switches. Import rejects automatic custom types or altered built-in types, matching definitions and automatic case settings; imported descriptions cannot redefine behavior.

Demo, beside Import / Export, opens a live page for enabled filters. It opens in the same tab with your current draft without saving preferences, and evaluates examples with all enabled rules together. Capture the page using Copy, Preview or Save in the popup: Demo uses the same draft, while ordinary pages use saved filters. Customize filters returns in the same tab and restores unsaved changes. Temporary navigation drafts stay in this tab, separately from saved extension preferences. Built-in examples are synthetic; custom examples may contain your matching terms. Rules without an automatic example link to Try filters.

In Try filters, choose Text or field value, Link URL, Page title or Page URL. Add a field label only for field values; other detectors work on the sample itself. Paste a complete query URL for URL-parameter rules. Demo uses a packaged DOM capture script in both browsers; other extension pages stay blocked and no extra permissions are needed.

Export immediately downloads a file with every filter in the table, including built-in definitions, on/off states and custom text rules. Import opens a file picker and loads the selected file directly into the table. Choose Save filters to apply it. The file also lists the available rule types and explains what each checks. Older filter exports remain supported; new built-in filters are added with their default states. Limits: 400 custom rows, 256 match characters per literal row or 4,096 per Regex row, 131,072 in total, and 1 MB per imported file.

Custom rule text is stored locally and included in filter exports. Review it before sharing. If saved filters cannot be read, redacted exports stop; reload filters or restore defaults and save to recover.

Preview and edit before copying

After selecting a block, the panel offers Preview & edit, Copy context, and Save to file. Each action uses only the selected block. Direct Copy adds the usual context boundaries; Save writes the text without boundaries through a temporary extension tab that closes on success. Firefox requests download permission when needed. The selection remains available after direct Copy or Save.

On Chrome and Firefox Desktop, Select element starts a picker and closes the popup. Point and click to choose one block. Use Select parent, Back, or Pick again to adjust it; focus a page element and press F2 for keyboard selection. Preview & edit opens the prepared block in the editor with your chosen settings. Esc or Cancel exits. Choices expire after five minutes and are not saved. The picker works in the main document of ordinary HTTP/HTTPS pages; selecting inside frames is unavailable. Accessible labels may refer to text outside the block. Android retains whole-page capture.

Choose Preview & edit, first in the action row, to open the prepared context in a separate tab. Keep the popup open until the editor is ready. Opening it does not copy anything or save a file. Edit the text, then choose Copy or, on Desktop, Save to file. Copy adds context boundaries automatically; saved files contain the editor text without boundaries. Your spaces and line breaks are preserved.

Reset changes restores the initially prepared text after confirmation. Counts below the editor show both the copy size with boundaries and the text/file size without them. Compression reduction and automatic redaction counts describe the original export before manual edits. Manual edits are not checked for sensitive data. Maximum contains packed references; use Compact for easier editing.

Your draft stays in this tab only. Closing or reloading it loses the text. To change the format, compression or privacy setting, return to the source page and open the popup again. Preview and Copy work on Desktop and Firefox Android. Saving edited drafts to a file is available on Desktop.

Firefox capture

Chrome 125 and later captures the main document and eligible embedded documents, including cross-origin frames. Hidden frames and tracking pixels are skipped; visible advertising may still appear. Documents below the viewport can be included. A warning indicates when some embedded documents could not be captured. Both browser builds omit password input values even when redaction is disabled.

The Firefox build reads the current page's HTML and ARIA semantics. It captures the main document, supported open web components and eligible same-origin frames. Enable Include frames from other sites to include available cross-origin frames. Hidden frames and tracking pixels are skipped; unavailable or changing frames produce a partial warning. Closed web components, canvas pixels and content that has not loaded remain outside its scope. This Firefox-only checkbox is off by default and works on Desktop and Android. Enabling it requests access to all HTTP/HTTPS websites in one browser prompt. Denial leaves it off. Access persists across tabs and browser restarts; turning it off removes site access. No Save preferences click is needed for this option. Capture still runs only when you use Copy, Preview, or Desktop Save; use the action again after changing the option. Protected frames may remain unavailable.

Password input values are always omitted in Firefox, including when redaction is off. Hidden labels can still contribute to control names. Collapsed content is not automatically opened or included.

If capture exceeds a page-size or time limit, or the page changes during capture, wait for the page to finish loading and try again. Browser pages and protected websites may deny access. Firefox capture does not need a debugger connection.

Open the extension from the browser toolbar to grant access to the current page. Reopen it after navigating to another site. Firefox Desktop supports Copy and Save. The same Firefox package supports Copy on Android; Save is unavailable. Without and Detailed can match when there are no removable wrappers, and Maximum can match Compact when additional encoding would not save enough space.

Firefox Desktop asks for download permission when you first choose Save to file. If you decline, Copy remains available. Firefox Save opens a separate extension tab to keep the file available when the file picker closes the popup. Keep that tab open until saving finishes; it closes after success and shows an error if saving fails or is cancelled. Chrome confirms completion while its popup remains open; otherwise check the browser download manager. If this browser does not support file downloads, Save is unavailable and you can use Copy page context.

Privacy is in your control

Redact sensitive data is on by default. It replaces detected credentials with [REDACTED] before the export reaches your clipboard or a saved file. Disable it only when you intentionally need original values.

What gets hidden

The filter looks for common credential patterns in captured text, field values, and URLs. Examples below use fictional values:

  • API keys such as sk-proj_abcdefghijklmnopqrstuvwxyz, GitHub tokens such as ghp_abcdefghijklmnopqrstuvwxyz123456, and AWS access key IDs such as AKIA1234567890ABCDEF become [REDACTED].
  • Authorization: Bearer abcdefghijklmnopqrstuvwxyz.12345678 becomes Authorization: Bearer [REDACTED]. Recognized Basic authorization values and JWTs are hidden too.
  • https://example.test/?token=example-token becomes https://example.test/?token=[REDACTED]. Values of api_key, secret, and password query parameters are also hidden.
  • Captured field values with labels containing English terms such as Password, Passcode, API key, Token, Secret, or Authorization are hidden. In ordinary text, assignments such as password: example-password are hidden when the value has at least eight characters.

What can remain visible

Names and postal addresses in ordinary text stay visible. Common email addresses are partially masked by default. Phone masking detects only the supported formats; full hiding is optional. English personal-field masking applies only to labelled values; checksum-based card and IBAN rules can miss malformed values. Ordinary text such as Token count: 42 also stays visible. A password written as plain text without a recognized label or pattern, or with an unrecognized label in another language, can remain visible.

These local pattern and checksum filters are not a complete personal-data anonymizer. Review the exported text before sharing it, even when redaction is enabled.

Review page content before sharing

Exported context can include text you did not see, such as white text on a white background, text covered by another element, or accessible labels. Inclusion depends on what Chrome exposes in its accessibility tree and what the export preserves. Hidden accessibility text can be legitimate; its presence alone does not mean a page is malicious.

The export does not include all HTML text. Content excluded from the accessibility tree, not yet loaded, or present only as image pixels may be absent. The extension does not perform OCR. Some hidden text can still contribute to an element's accessible name.

Visible or hidden page text can contain instructions aimed at an AI assistant, often called prompt injection. These may ask it to ignore your task, reveal private information, or take unrelated actions.

  • Review the exported text before sharing it, and remove suspicious or irrelevant instructions.
  • Tell the assistant to use the page as source material rather than instructions to follow.
  • Review consequential actions, such as sending information or changing data, before allowing them.

Local processing, credential redaction, compression, and export boundaries do not detect or guarantee removal of malicious instructions. These review steps can help reduce risk, but they do not guarantee protection.

If something does not work

This page cannot be captured

Browser-internal pages, extension stores, and some protected websites cannot be captured. Try a regular web page.

Capture is busy or fails

In Chrome, close competing DevTools sessions and try again. In Firefox, wait for the page to finish loading, reopen the extension, and retry.

Data controls and local diagnostics

Open Diagnostics & data controls from the popup to exclude document titles, reduce or omit URLs, and exclude current form values. Organization restrictions take priority. After changing data settings, prepare context again. Mandatory organization exclusions make Preview read-only.

The local technical journal defaults to Error, with Off, Info and temporary Debug options. It excludes page content, URLs, titles, form values, filenames and filter text. Default retention is at most 1000 events, 2 MiB of serialized data and seven days; entries expire during access. Personal Debug ends after 30 minutes. Clear journal removes retained entries unless your organization disables manual clearing.

Use Capture sources in Diagnostics & data controls to save personal blocked sites or enable Only allow these sites. Enter one origin pattern per line, such as https://example.com or https://*.example.com. An enabled empty allowed list blocks all external captures. Personal restrictions apply to pages, selected elements and embedded frames, and cannot override organization restrictions. Prepare context again after changing them.

Optional capture history is off by default. Enable it in Diagnostics & data controls to retain page headers and selected element tags, without captured contents. Defaults are 60 days and 10 MiB; choose 1–365 days and 1–50 MiB. Organization settings can lock these choices and separately prohibit manual clearing. Automatic retention continues. View recent captures, clear history, or explicitly copy/save its JSON. History never enters the technical report automatically.

Review the diagnostic JSON before copying or saving it. The report excludes internal domain lists and rule text. Journal entries are included only if you choose them. Export restrictions also apply to diagnostic reports. Nothing is sent automatically.
