Copy as Context

Turn the open page into useful context.

Export page context for AI chats without manually cleaning or restructuring it.

Everything is processed locally in your browser

Getting started

A quick export in three steps

1

Open a page

Open the extension on the tab you want to capture.

2

Choose settings

Set Compression. Expand Options to change the format or redaction.

3

Export context

Choose Copy context or Preview & edit. Save to file is also available on Desktop.

Compression and format

Without

Keeps every captured semantic node, not all HTML text.

Detailed

Removes unnamed wrappers without semantic attributes; keeps text, links and states.

Compact

Removes repeated accessibility noise while keeping meaningful controls. The default.

Maximum

Packs Compact context using abbreviations and shared references, with a legend. Falls back to Compact when packing adds overhead. Token savings vary by page and model.

Export format

Semantic Text gives a concise outline; Markdown adds formatting for notes or AI chats.

Changed settings apply to the next export. Remember settings stores compression, format and redaction for future popup openings. Shortcuts use saved settings or defaults.

Desktop shortcuts

Use Alt+Shift+P for Preview & edit, Alt+Shift+C for Copy context, Alt+Shift+S for Save to file, and Alt+Shift+E for Select element. On macOS, use Option+Shift with the same letters.

Preview, Copy and Save shortcuts capture the whole page using saved settings and current organization policies. Keep the source page focused for Copy. A check mark on the extension icon means success; ! means failure. Hover for details. Repeated shortcuts are ignored during an action.

Save shortcuts open a temporary tab that closes after saving; keep it open until completion. Firefox requests download permission when needed.

Open Shortcuts in the popup footer to change assignments. Chrome uses chrome://extensions/shortcuts; Firefox uses Manage Extension Shortcuts at about:addons. Check for browser, system or keyboard-layout conflicts if a shortcut fails.

Capture and export

Preview, edit or select a block

Preview & edit opens prepared context in a separate tab without copying or saving. Keep the popup open until it is ready. Edit directly or use Find and replace, with optional Match case, Previous/Next, Replace or Replace all. Reset changes restores the original text after confirmation.

Copy adds context boundaries; Desktop Save to file saves the text without them. Spaces and line breaks are preserved. Counts distinguish copy and file sizes; compression and redaction counts describe the original export. Manual edits are not checked for sensitive data. Use Compact for easier editing; Maximum contains packed references.

On Desktop, Select element closes the popup and starts a picker. Click a block, then adjust it with Select parent, Back or Pick again. For keyboard selection, focus a page element and press F2. The panel’s Preview, Copy and Save actions export only that block. Esc or Cancel exits; selections expire after five minutes.

The picker supports the main document of ordinary HTTP/HTTPS pages, not frame contents. Accessible labels may refer to text outside the selected block. Android supports whole-page capture only.

Preview drafts stay in their tab; closing or reloading loses them. To change export settings, return to the source page and prepare context again. Preview and Copy work on Desktop and Firefox Android; file saving is Desktop-only.

Browser capture and saving

Chrome 125+ captures the main document and eligible embedded documents, including cross-origin frames, through its accessibility structure. Firefox reads HTML and ARIA semantics, including supported open web components and same-origin frames, without a debugger connection.

Both skip hidden frames and tracking pixels; visible ads and documents below the viewport may be included. Unavailable or changing frames produce a partial-capture warning. Capture does not open collapsed content, read canvas pixels or perform OCR. Unloaded content and closed web components may be unavailable.

In Firefox Options, Include frames from other sites is off by default on Desktop and Android. Enabling it requests access to all HTTP/HTTPS sites; denial leaves it off. Access persists across restarts, and switching it off revokes access. This option needs no Remember settings click. Run capture again after changing it; protected frames may still be unavailable.

Open the extension from the toolbar to grant current-page access, and reopen it after navigating to another site. If capture hits a size/time limit or the page changes, wait for loading to finish and retry. Compression levels can produce the same output when there is nothing more to remove or pack.

Firefox Desktop requests download permission on first save; declining still allows Copy. Firefox saves and selected-block saves use a temporary tab. Keep it open until saving finishes; it closes on success. For Chrome popup saves, keep the popup open for confirmation or check the download manager. Save is unavailable on Android or browsers without download support.

Privacy and data

Redaction filters

Expand Options and choose Filters beside Redact sensitive data. Toggle built-in rules or use + Add filter for custom rules. Matches become [REDACTED] or are partially masked. Password input values are always omitted, even with redaction off.

Custom rules

Give each row a name, choose one Rule type and enter matching text. Enable Case sensitive when needed. Use Duplicate to copy a configurable built-in rule; disable the original if the copy should replace it. Automatic built-ins use fixed detection rules; you can switch them on or off.

  • Text hides literal alternatives separated by / (space, slash, space), for example client name / internal.example. Commas and ordinary path slashes remain literal. Text — single literal treats the entire cell as one phrase.
  • Field labels hides values and nested text under labels containing a term. Field labels — whole words requires word boundaries. Both keep labels visible.
  • URL parameters hides query values while keeping parameter names. Enter names such as token / client_key, without ?, &, =, # or line breaks.
  • Authorization, JWT and Assigned secrets recognize credentials by scheme, token prefix or assignment label. Their matching details appear on the Filters page.
  • Regex hides complete matches. Insert example… provides email, GitHub, AWS, OpenAI and order-ID patterns. Enter expressions without surrounding slashes or flags; use | for alternatives. RE2 syntax excludes lookarounds and backreferences. Empty matches are ignored and existing redaction markers preserved.

Use separate rows to check the same terms in different contexts.

Automatic protection

These built-ins need no matching text or case settings. Full hiding overrides masking, regardless of row order.

  • Email masking is on by default: abcdef@gmail.com → abc***@gm***.com. It keeps half the characters of each name/domain part, rounded down and capped at three; the final suffix stays visible. Full email hiding is optional.
  • Phone masking is on by default and keeps up to three digits using the same half-length rule, preserving formatting: +380 50 123 4567 → +380 ** *** ****. Detection accepts 8–15 digits with +/00 prefixes or English phone-label context. Unlabelled local numbers can remain visible. Full hiding is optional.
  • Payment card and IBAN hiding is on by default. They check number length and checksums, accepting common separators. A match does not verify that an account exists.
  • Personal-field masking is on by default for English labels. Names and addresses keep up to three characters using the half-length rule; phones and emails use their masks. Documents, birth dates, financial details and CVV/CVC are hidden completely. Labels stay visible and nested values are protected. Optional full hiding covers the whole value. Names and addresses in ordinary prose are not detected. The supported labels appear in Text / matching rule.

Test and save

Expand Try filters. Test all checks enabled rules; Test selected checks the chosen rule even when off. Both use unsaved edits. Matched rules checks the original sample, so counts may overlap.

Choose what to test: text/field values, link URLs, page titles or page URLs. Add a Field label for field tests or a complete URL for parameter rules. Use Load example, Load near miss or your own sample. Test text is not saved.

Demo opens a sample page using your unsaved filters. Capture it from the popup to see their effect; ordinary pages still use saved rules. Customize filters returns to your draft. Examples are synthetic but may contain your custom terms.

Save filters applies edits to future exports with redaction on; existing previews stay unchanged. Reload saved discards unsaved edits. Restore defaults removes custom rules and resets built-ins in the form; save to apply.

Export downloads all filter definitions, custom text and on/off states. Import loads them into the table; choose Save filters to apply. The Filters page lists rule-size and import limits.

Filter text is stored locally and included in exports; review it before sharing. If saved filters cannot be read, redacted exports stop. Reload filters or restore defaults and save to recover.

Privacy and redaction limits

Redact sensitive data is on by default. It hides recognized credentials and applies enabled masking rules before export. Disable it only when you need original values.

Credential filters cover common API keys, GitHub tokens, AWS access key IDs, Authorization values, JWTs, secret URL parameters and English sensitive-field labels. For example, ?token=example-token becomes ?token=[REDACTED]. Assigned secrets such as password: example-password require at least eight value characters.

Unrecognized patterns or labels in other languages can remain visible. Names and addresses in prose are not masked; phone detection covers supported formats only, and checksum rules can miss malformed card or IBAN values. Harmless text such as Token count: 42 remains visible.

Local filters are not a complete personal-data anonymizer. Review exported text before sharing, even with redaction enabled.

Review page content before sharing

Exports may include accessible labels or text hidden by styling or overlapping elements. This can be legitimate. Capture follows browser semantics, so some HTML text may be absent.

Visible or hidden page text may contain prompt injection: instructions asking an AI to ignore your task, reveal information or take unrelated actions.

  • Remove suspicious or irrelevant instructions before sharing.
  • Tell the assistant to treat page content as source material, not instructions.
  • Review consequential actions before allowing them.

Local processing, redaction, compression and context boundaries do not detect or guarantee removal of malicious instructions.

Data controls and diagnostics

Open Data controls from the popup to exclude titles or form values and reduce or omit URLs. Organization restrictions take priority and can make Preview read-only. Prepare context again after changing data or source settings.

Capture sources blocks sites or enables Only allow these sites. Enter one origin pattern per line, such as https://example.com or https://*.example.com. An enabled empty allowed list blocks all external captures. Restrictions cover pages, selected blocks and frames, and cannot override organization rules.

The technical journal records technical results, excluding page content, URLs, titles, form values, filenames and filter text. Error is the default; Off, Info and 30-minute Debug are available. Default retention is up to 1,000 events, 2 MiB and seven days. You can clear entries unless your organization restricts it.

Capture history is off by default. It keeps page headers and selected-element tags, without captured contents, for 60 days/up to 10 MiB by default. You can change retention, view or clear entries, and copy/save history as JSON. Organization rules may limit these choices. History is never included in technical reports automatically.

Review diagnostic JSON before copying or saving. Reports exclude internal domain lists and rule text; journal entries are opt-in. Export restrictions apply to reports too. Nothing is sent automatically.

Help and links

If something does not work

This page cannot be captured

Browser pages, extension stores and protected sites may block capture. Try a regular web page.

Capture is busy or fails

Chrome: close competing DevTools sessions. Firefox: wait for loading, reopen the extension and retry.
