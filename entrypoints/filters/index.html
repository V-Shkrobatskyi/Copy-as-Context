How to use filters

Use Duplicate to create an editable copy of a configurable built-in filter. Automatic built-ins have no Duplicate action. Turn the original off if you want your copy to replace it. Choose one Rule type for each custom row. To check the same terms in another place, add another row.

Automatic email, phone, card, IBAN and personal-field types are built-in only. They need no matching text or case settings; use On to enable or disable them. Other types except Regex use literal names or prefixes. Use / (space, slash, space) between literal alternatives; commas and ordinary URL/path slashes are literal. Text hides literal alternatives. Text — single literal treats the entire cell as one phrase, preserving older rules. Case sensitive applies to the selected type.

Field labels hides the value and nested text of a matching field, keeping its label visible. Field labels — whole words requires word boundaries; Field labels uses substring matching. URL parameters hides values in ?name=value and &name=value; enter names without ?, &, =, # or line breaks.

Rule types and examples

Authorization: scheme names such as Bearer / Basic / CustomAuth, followed by whitespace and a credential of at least 8 characters. The scheme stays visible.

JWT: first-segment prefixes such as eyJ. Requires three dot-separated segments: at least 5 characters after the prefix in the first segment, and at least 5 in each remaining segment. Segments use letters, digits, underscores and hyphens.

GitHub tokens: prefixes such as ghp_ / github_pat_ / company_, followed by at least 20 letters, digits or underscores. AWS keys: prefixes such as AKIA / ASIA, followed by exactly 16 uppercase letters or digits (lowercase is also accepted when Case sensitive is off). OpenAI keys: prefixes such as sk- / sk-proj-, followed by at least 16 letters, digits, underscores or hyphens.

Assigned secrets: names such as api_key / token / private_key, followed by : or = and a value of at least 8 characters. Whitespace, &, quotes, commas and semicolons end the value. The label and separator stay visible.

Mask email addresses (including domains) is enabled by default: abcdef@gmail.com becomes abc***@gm***.com. The name and each domain label keep half their characters, rounded down and capped at three visible characters; the final domain suffix remains visible. One-character parts become *. Hide email addresses is off by default and hides the whole address when enabled. Full hiding from overlapping rules always wins, regardless of row order. Both types work automatically without matching text or case settings, recognize common email formats, and follow the master Redact sensitive data setting. Masking is stable on repeated processing.

Regex hides matching text, field values, links and metadata. Choose Insert example… in a custom Regex row for email addresses, GitHub tokens, AWS keys, OpenAI keys or order IDs. Enter the expression without surrounding slashes or flags. Use | for alternatives, not / . Case sensitive sets the default letter-case matching. Lookarounds and backreferences are not supported. Empty matches are ignored; existing [REDACTED] markers are preserved.

Regex examples match common formats, not every possible email address or a verified credential. You can edit them and test your own sample. Matching rules allow 256 characters, or 4,096 for Regex; all rules together allow 131,072 characters. Import files can be up to 1 MB.

Credential detectors require word boundaries, matching the built-in behavior. These are credential-shape checks, not cryptographic validation. Older rules with several modes become separate rows, preserving every check. Older GitHub, AWS and OpenAI custom types become equivalent Regex rules. Duplicate includes all built-in aliases and settings.
